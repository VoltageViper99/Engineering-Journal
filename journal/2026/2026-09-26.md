## Work completed

- Switched the container update tool to a maintained fork, because the original project was archived.
- Capped its log size so a repeating error cannot fill the disk.
- Gave its notifications a dedicated topic. The old one was shared with an unrelated project, which made update notices look like random errors.
- Removed a self-hosted Git service that was no longer used.

## Why

An update tool that is unmaintained or noisy is worse than none. Removing unused services shrinks what needs patching and watching.

## What I learned

- A shared notification topic can look like a fault. Check the source before debugging the symptom.
- Unbounded logs are a disk-space incident waiting to happen.
