> [!NOTE]
> **In short:** I gave the Control Centre, the dashboard I run my server from, a new look and rebuilt its pages one group at a time. Along the way it gained a real command line in the browser, live log viewing, a page showing whether my backups are fresh, and buttons to bring a whole group of containers up or down. I then made every page work properly on a phone. Each step was small enough to test on the real server before the next one.

New to some of the terms? The [glossary](../../GLOSSARY.md) explains them in plain English.

## What I worked on

The [Control Centre](../../projects/control-centre.md) had grown one page at a time, and the pages no longer looked like they belonged together. Between 24/10 and 28/10 I replaced the look and then the pages behind it. The new design is called Nocturne: a dark background, one violet accent colour and two fonts, one for headings and one for numbers.

I used Claude to write the code. I set the order, chose between the options it offered at each step, installed every change on the real server and checked it before the next one began.

## What changed

I broke the rebuild into phases so that a mistake in one never held up the others.

| Phase | What it did |
| --- | --- |
| 1 to 2 | A new frame (sidebar, top bar) and a new Overview page, plus shared pieces: a command palette (press a key and type where you want to go), a confirm dialog, pop-up messages and menus. |
| 3 | The Docker pages: stacks, containers, images, volumes and networks, then the container detail page and the upgrade and restore actions, then Maintenance. |
| 4 | System and Storage, then Weather, Updates and the invoicing pipeline, then the Cloudflare page, then Settings and Login. The old theme picker for the dashboard was removed. |
| 5 | **Terminal.** A real shell in the browser, behind the same login and checks as the rest of the dashboard. |
| 6 | Deleted the old code that nothing used any more. |
| 7 | **Live logs.** Follow a container's log, or the server's own journal, as it happens. |
| 8 | **Backups.** Shows each backup snapshot, how its last job went and whether the repository checks out, and raises an alert if a backup has gone stale. |
| 9 | **Compose actions.** Pull, Up and Down for a whole group of containers at once, and a read-only view of how the group is defined. |
| 10 | Removed leftover styling and the helpers that were only keeping it alive. |

Smaller pieces landed around them:

- **Disk space.** A disk explorer that lets me drill into what is using space, a "host disk hogs" card, a seven-day estimate of when a disk will fill, and a card showing how much space snapshots hold. Alerts now name the filesystem that is full instead of just saying "disk".
- **Phone layout.** In three steps: a bottom tab bar and a "More" sheet, tables that turn into cards with icons instead of words, and the live log controls fitted to a narrow screen.
- **Music, for the last time here.** Real live spectrum for the visualiser, six new visualiser styles, and then a phone layout for the music pages. A week later I moved the music app out of this project altogether (see [the next entry](2026-10-31.md)), so this was the last of that work in the Control Centre.
- **Branding.** A logo, a browser tab icon and a login background, and a short front-page README with separate guides instead of one long one.

## Problems / debugging

- **The dashboard would not start without one optional library.** The terminal needs a library for browser connections that stay open. On a machine without it installed, the whole dashboard crashed at start-up instead of just turning the terminal off. I changed it so a missing library switches only that feature off.
- **A shared database connection with no lock.** The dashboard keeps one open connection to its database that several background jobs share. Two of them could use it at the same moment. I put a lock around it. Nothing had failed yet, which is exactly when it is cheapest to fix.
- **A custom terminal service being overwritten.** My installer replaced a terminal service file I had adjusted by hand. It now keeps a custom one and restarts it.
- **Numbers that were wrong on a phone.** The counts on the filter pills in the Docker pages did not match the lists, and long values spilled out of their cards. Both fixed in the phone work.

## Decisions

- **One look, no theme picker.** The Windows-era themes are fun, but the dashboard is a work tool. One consistent design is easier to keep correct on a phone.
- **A terminal in the browser needs to be earned.** It sits behind the login, a one-time token and a check that the request comes from the dashboard's own page. It is only reachable from my own devices, never from the internet.
- **Alerts for stale backups, not just failed ones.** A backup that silently stopped running looks fine until the day I need it, so the page shows the age of the last good one.
- **Dead code goes in its own step.** I removed unused code in separate phases so a deletion could never be hidden inside a change that adds something.

## What I learned

- Splitting a redesign into ten small phases meant I could stop at any point with a working dashboard.
- Test on the phone you actually use. Numbers and cards that looked right at a desktop size were wrong at phone width.
- A feature that needs an optional library should fail alone and politely, not take the whole app down with it.
