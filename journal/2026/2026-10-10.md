> [!NOTE]
> **In short:** I had a pile of old data discs to back up, so I wrote a small Python program that copies each disc to the server, ejects it and moves on to the next. I wrote most of it myself, to learn Python on something I would really use. A bad disc is reported and skipped instead of stopping the whole batch.

New to some of the terms? The [glossary](../../GLOSSARY.md) explains them in plain English.

## What I worked on

A script to back up a pile of old data discs using the server's disc drive. Project page: [CD Backup Script](../../projects/cd-backup.md). I built it over two days (09/10 and 10/10) and wrote most of the core myself, as a way to learn Python on something I would actually use.

## What changed

- Started with a skeleton that read the disc label, then added mounting, a copy into a per-disc folder, and unmount and eject.
- Added a wait-and-retry for a drive that is still spinning up, and a loop to do several discs in one run.
- Added error handling so a failed disc is reported, cleaned up and ejected, and the batch carries on.
- With AI assistance, added a live progress bar, handling for Linux discs, a full-screen interface and optional sound effects.
- Wrote a plain-English notes file on the Python syntax I used.

## Problems / debugging

- **Mounting over SSH asked for a password.** Over SSH Linux does not treat me as sitting at the machine, so it wanted an administrator password. A script that stops for a password cannot run a batch.
- **The prompt loop misbehaved** twice before it handled "another disc?" and quitting properly.
- **Failures left a mess:** a half-copied folder forced the next try onto a numbered name. I made clean-up and eject happen however the copy ends.
- **Linux discs** have root-only files and broken shortcuts that would otherwise fail a whole disc.

## Decisions

- Added a small polkit rule so the optical-drive group can mount that one drive without a password, instead of running the script as root. I tested it, and deleting the rule file rolls it back.
- Dry run by default, and never overwrite an existing folder.
- Skip unreadable files and list them, instead of failing the whole disc.

Why: the aim was a tool I can leave running while I swap discs, so it has to be safe to fail. Giving a hobby script root would be a wider permission than the job needs.

## What I learned

- Writing the core myself taught me more than reviewing generated code would have. Functions, exceptions, `try`/`finally` and subprocess calls all stuck because I had to get them working.
- Decide what happens on failure first. Always ejecting and removing partial copies came from that.
- Keep the engine separate from the interface. The full-screen version only needed to react to progress messages from the same code.
- Test on the real hardware. The password prompt would not have shown up any other way.

## Next steps

- Check there is enough free space and that the destination is writable before mounting.
- Verify each copy against the disc (file count and size).
- Tidy odd characters out of disc labels.
