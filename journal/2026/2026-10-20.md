### Keeping the AI on a short lead

I wanted a playlist helper that understands a plain sentence, but I did not want a model choosing songs. It is easy for a language model to invent an artist or a track that is not in my library. So the design is:

- The model only **translates** the sentence into form fields. The normal playlist generator still picks the tracks, so it cannot invent songs.
- Every answer is **checked again in Python**. A style must be one that exists in my library, and an artist must be in my library **and** named in my sentence. Anything dropped is shown as a note, so I can see what was ignored.
- Numbers (years, length, track count) and phrases like "getting heavier" are read by plain code, not the model.
- It only **fills the form**. Nothing is generated or saved until I press Generate.
- The model runs on my own server and is reached only from the server itself. If it is down or slow, the helper turns itself off for a minute after three failures and the normal form keeps working.
- The feature is **off by default** and switched on in the config.

## Problems / debugging

- **"Bad parameter or other API misuse".** The music app shared one SQLite connection between all its threads. Under several requests at once this raised odd errors, and one of them could sign me out. Giving each thread its own connection, the same pattern the dashboard already used, fixed it.
- **A saved theme that did not stick.** After pressing Apply, the page fell back to Windows 98. The code that read the saved theme did not expand `~` in the database path, so it silently looked in the wrong place. It now uses the same path handling as the rest of the app.
- **A "no <artist>" request ignored.** An early version of the AI helper could drop an artist I had asked to skip. Skip requests written in the sentence are now always honoured, and styles named in the sentence are used directly.

## Decisions

- **Themes are tokens, not copies.** Each theme is one small file of colours, borders and fonts. The page layout reads those values, so adding a theme does not mean copying any HTML. Each theme has an automated readability (contrast) check.
- **Preview, then keep or revert.** Any change that could make the page unreadable needs a timed undo.
- **A local model, not a cloud one.** My listening habits stay on my server, and there is no API bill.
- **Off by default.** New features that depend on another service ship switched off.

## What I learned

- An AI feature is safest when it can only suggest, and plain code checks everything it says.
- Silent fallbacks hide bugs. The theme fell back to the default without any error, which looked like the save was broken rather than the read.
- SQLite is fine for a small app, but a single connection shared between threads is not.
