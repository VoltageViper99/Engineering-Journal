> [!NOTE]
> **In short:** I rebuilt the music page on my home dashboard so it looks and works like the old Windows Media Player, styled to match whichever version of Windows the dashboard is dressed as. I did it in 17 small steps, testing each one on my tablet and phone before the next. Along the way I fixed a start-up bug that broke playlists for hours after a reboot, and I can now choose which speaker the music plays through, including the phone in my hand.

New to some of the terms? The [glossary](../../GLOSSARY.md) explains them in plain English.

## What I worked on

The music app in my [Control Centre](../../projects/control-centre.md) had grown one control at a time, and it showed. It worked, but it felt messy, and I use it every day. On 21/10 I turned it into something that looks and works like a desktop media player, matched to each Windows theme from the [previous entry](2026-10-20.md). I use it from a tablet and my phone as well as the **kiosk** (the computer that shows the dashboard full screen and plays the music), so every step was checked on all three sizes.

The code was written with Claude. I set the order of the work and the rules, chose between the options at each step, installed every change on the real server and tested it on my own devices before the next one started.

## How I ran it

Before any code, I agreed a plan in phases, with rules for every step:

- **One change per pull request** (a proposed change I review and approve before it goes in), each with tests and screenshots in all eight themes and on a phone.
- **Nothing merged or installed without me.** I reviewed each pull request, merged it, installed it on the server and tried it before the next one.
- **Original artwork only.** The skins are drawn in code to look like the era, not copied from Windows.

That gave 17 pull requests to the dashboard in one day. It sounds like a lot, but it was the point. Because each one was small, a problem I found on the tablet could be fixed in the next one instead of being buried in a large change.

## Problems / debugging

### Smart Playlists that never finished loading

After the server rebooted, the Smart Playlists page said "still loading" and stayed that way for hours. Nothing looked broken, which made it the most annoying kind of bug.

The cause was a race at start-up. My music app has to read the whole music library before Smart Playlists can work. After a reboot it started *before* the music server was ready (the music server runs in a **container**, a sealed box Docker starts for it), so the first read failed. The app would not try again for six hours, and it did not write the failure to its log, so there was no clue anywhere.

The fix has three parts:

- **Try again sooner.** After 30 seconds, then doubling each time, up to every ten minutes.
- **Leave a note.** The failure and the recovery are both written to the log now, so next time I can see it.
- **Wait your turn.** The app now waits for Docker to be ready before it starts.

The nice surprise: once this was installed, the AI playlist helper from the [previous entry](2026-10-20.md) finally worked end to end on the real server.

### The smaller ones

- **A faded "fi" on a button.** "Confirm upgrade" looked wrong in the pixel font. Turning off font ligatures (where a font joins letters like "fi" into one shape) was the obvious fix, but when I checked, the bundled font cannot form ligatures at all. The fade went away after the fix was installed and the server was rebooted for updates at the same time, so I honestly do not know which one fixed it. I wrote that down instead of claiming the fix worked.
- **Station names that did not match my library.** The radio log could not match "Motley Crue" to "Mötley Crüe" or "Beatles" to "The Beatles". Artist names are now compared without accents, a leading "The", or "&" versus "and".
- **The tablet in portrait.** Screenshots at phone and desktop sizes looked right, but the real tablet held upright showed a column one letter wide. Testing on the device I actually use found what the screenshot sizes missed.
- **The phone could not reach anything over mobile data.** Tailscale (the private network that links my devices) said "Connected" and the server answered a ping, but no service would load by name. The internal names only resolve through Tailscale's DNS (the phone book that turns names into addresses). Turning on "Use Tailscale DNS" in the app, and setting Android's Private DNS to Automatic, fixed it.
- **Safari and streamed audio.** A browser playing a track asks for it in many small pieces. The server now keeps the last two tracks, so each piece does not fetch the whole track from the music server again.
- **Wrong port in my own docs.** My homelab notes listed the music app's firewall rules against an old port number. I corrected the documentation to match what the proxy really uses. A small thing, but notes that are wrong are worse than no notes.

## Decisions

- **One shared queue, a choice of speaker.** Rather than a separate queue per device, there is one queue, and the speaker setting decides where it is heard. That keeps "what is playing?" a single answer.
- **Switch between paired speakers only.** Pairing a new Bluetooth speaker stays a hands-on job at the kiosk. The page only switches between speakers that are already paired, which keeps what the web page can do to the kiosk small.
- **No automatic Bluetooth reconnect.** The kiosk used to try to reconnect every minute. I turned that off. If a speaker drops, I pick it again in Settings, so the kiosk never fights my choice.
- **Edit only my own playlists.** Only playlists my music login owns can be changed, smart playlists stay read-only, and every change is read back and checked. A delete only goes through if it names the playlist's current name.
- **No password prompt for the station manager.** It is behind the normal login and only reachable inside my network, so a second prompt added nothing.
- **Visualisers parked.** They were in the plan, but they are not something I need. A design for showing the player on other screens is the last planned phase.

## What I learned

- Small pull requests let me test each step on real devices and change direction cheaply. I dropped a layout the same morning it was built, and it cost nothing.
- Test on the device you actually use. My tablet held upright found problems no screenshot size did.
- When two changes happen at once, such as a fix and a reboot, say you do not know which one worked.
- "Connected" in a VPN app does not mean name lookups go through it.
