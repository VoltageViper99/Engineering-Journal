> [!NOTE]
> **In short:** My music player lived inside the dashboard I use to run the server, which meant a music bug could get in the way of server work. I moved it into its own app called Voltage Music, with its own login and its own data. The screen that used to play the music has been retired, so the server now plays the music itself, with no gaps between songs, through a Bluetooth adapter. I also gave the player a new look that is easy to read from across the room.

New to some of the terms? The [glossary](../../GLOSSARY.md) explains them in plain English.

## What I worked on

The Control Centre started as a dashboard, picked up a music player and then outgrew it's original intended use. It worked, but the two did not belong together. A player is something my family uses in the evening. A server console is something I use when something is wrong. I wanted a fault in one to be unable to touch the other.

Two other things made it the right week for it:

- The **kiosk** (the computer that showed the dashboard on a screen and played the music) was being retired. That removed the only way the server could make sound.
- I had a design for a new music interface that I wanted to try, and a clean new app is the right place to start it.

I used Claude to write the code. I decided the split, the order, what should and should not move, and I tested everything by listening to it.

## What changed

**The split**

- A new app and a new repository, **Voltage Music**, with its own database, login, settings and service. The old music code stays in place until I say, so I could go back.
- A one-way **import tool** that copies the play history, loudness measurements, radio stations and favourites across. It opens the old database read-only, compares counts after the copy and refuses to run over data that is already there.
- The Control Centre goes back to being just the infrastructure console. Music, the kiosk code and the theme system came out of it.
- A health feed my business portal reads was **pinned with a test**, so cutting code out of the Control Centre could not quietly change what the portal sees.

**Sound from the server**

- The server now plays the queue itself with **mpv**, a command-line audio player the app controls, into a Bluetooth adapter plugged into the server. Closing the browser no longer stops the music.
- **Gapless playback.** The next track is lined up before the current one ends, so albums that run into each other do not get a gap.
- Volume levelling is done by my own code, which measures each track once and stores a gain. I switched mpv's own ReplayGain off explicitly, so the two cannot stack up and make the music quieter than it should be.

**The new design, "Cell"**

- Violet on near-black, two fonts, one accent colour. Pages for Now Playing, the queue, a home page of recent albums, artists and album detail, playlists you can rename, reorder and edit, radio, history, the station log, a smart playlist generator and settings.
- After a day of using it I asked for changes: a Back button, the current menu item highlighted, the name changed to "Voltage Music", bigger artist, album and "up next" text so I can read them from across the room, a smaller cover on the Now Playing page, roomier forms and spacing, and artists counted by albums rather than songs. I also took out a battery-style percentage that was extra noise.
- I removed options I will not use: crossfade, an "energy mix", similar artists and an output chooser.
- The old interface came out the next day, after I had lived with the new one.

## Problems / debugging

- **The idle lock never locked.** The app logs me out after a while of not being used. The new page checks for changes every second, and that check counted as "using" the app, so it never timed out. Those background checks no longer count.
- **Missing fonts.** The new design asked for fonts the new app did not ship, so every page quietly used a fallback. I found it when the pages looked off, and copied the fonts across.
- **A test failed after I wrote it.** I had assumed mpv reports "ReplayGain off" as the word "no". It reports it as false. I fixed the test and the code that reads it.
- **Cutting over safely.** The order matters: the new app first, check it, then slim the old one. I wrote the order into the deploy notes before doing it.

## Decisions

- **Own app, own login, own data.** No shared database and no shared password. It costs a copy of about a thousand lines of login and settings code, and in return the two apps cannot take each other down.
- **Copy, do not share, the common code.** Two stable apps with a copied helper are easier to live with than one shared library that both depend on.
- **Take the options I do not use out.** Crossfade and similar artists sounded good in the plan and I would not have used them. Removing them took minutes and the settings page is cleaner for it.
- **A one-command update.** A small script checks, pulls, installs, restarts and verifies, and refuses to run as root because root has no GitHub login.

## What I learned

- A split goes more smoothly when the old code keeps working until the new one is proven.
- "No" is not the same as false. Read what a program really reports.
- A page that polls to look alive can keep a session alive too.
- Living with a design for a day is worth more than another round of mock-ups.
