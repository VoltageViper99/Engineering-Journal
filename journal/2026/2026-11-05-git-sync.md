> [!NOTE]
> **In short:** I built `git-sync`, a Bash script that recursively discovers and pulls updates from every Git repository under a given directory. It skips repositories with uncommitted or untracked changes, uses `--ff-only` to prevent merge commits, reports failures per-repo, and continues processing the rest. Useful for keeping a server's repository fleet in sync without manual intervention on each one.

## What I worked on

The script solves a common automation problem: keeping multiple Git repositories up-to-date on a server or workstation without running `git pull` individually in each one. It's read-only (pull-only), safe to run on a timer, and designed to fail gracefully per-repository rather than stopping at the first problem.

## The script


**Usage:**
```bash
./sync-repos [directory]
```

With no directory argument, it searches recursively from the current directory. Example:
```bash
./sync-repos ~/directory
```

**What it does:**

1. Recursively finds all `.git` directories under the given path.
2. For each repository found:
   - Checks for uncommitted or untracked changes using `git status --porcelain`.
   - **Skips** any repo with uncommitted work (preserves local changes).
   - Attempts a `git pull --ff-only` if the working tree is clean.
   - Reports success or failure per-repository.
3. Continues with other repositories even if one pull fails.
4. Prints a summary: count of pulled, skipped, and failed repositories.
5. Exits with status 0 only if all attempted pulls succeeded (exit 1 if any failed).

**Example output:**
```
Pulling: /home/user/projects/repo1
Pulling: /home/user/projects/repo2
Skipping (uncommitted changes): /home/user/projects/repo3
Pulling: /home/user/projects/repo4
Failed: /home/user/projects/repo5

Done: 3 pulled, 1 skipped, 1 failed.
```

## Key design decisions

- **`--ff-only` only.** Prevents accidental merge commits. If a repository cannot be updated with a fast-forward, it's reported as failed, not merged. Human review is expected for repos in that state.
- **Skip dirty repos.** Uses `git status --porcelain` (not `--quiet`) to detect both uncommitted changes and untracked files. Repos with local work are left untouched.
- **Continue on failure.** Rather than stopping at the first failure, the script processes all repositories and reports failures at the end. Makes it suitable for automated runs.
- **Exit status signals success or failure.** Returns 0 only if `failed_count == 0`, so it can be used in conditional workflows (e.g., run a post-sync task only if all pulls succeeded).
- **No credentials.** Assumes remotes are already configured and authentication is set up (SSH keys or credentials cached). It never prompts for passwords or interacts with authentication.

## Common use cases

1. **Periodic sync on a server:** Run via cron or systemd timer to keep repositories in sync without manual intervention.
   ```bash
   0 * * * * /path/to/sync-repos ~/projects >> ~/sync.log 2>&1
   ```

2. **Before a backup or deploy:** Ensure all repositories are up-to-date before running a backup or deploy script.
   ```bash
   ./sync-repos ~/directory && ./backup.sh
   ```

3. **Local workstation with multiple projects:** Quickly update all projects:
   ```bash
   ./sync-repos ~/directory
   ```

## Troubleshooting

**Repositories stay skipped:**
- The repo has uncommitted or untracked files.
- Clean the working tree (`git add`, `git commit`, or `git clean`) and re-run.

**Pull fails with "fatal: Not a git repository":**
- The `.git` path is not where expected (rare; worth investigating).
- Run `git -C /path/to/repo status` manually to debug.

**Pull fails with "error: Your local changes to ... would be overwritten":**
- The repo has uncommitted changes that conflict with incoming commits.
- Manually review and resolve in that repository.

**Pull fails with "error: update_ref failed":**
- Usually indicates corruption or permission issues in the `.git` directory.
- Manually inspect `git fsck` output or check file permissions.

## What I learned

- **Safe recursion with null-terminated paths.** Using `find ... -print0` with `read -d ''` safely handles repository paths with spaces or special characters.
- **Silent success, loud failure.** The script prints each pull attempt and failures to stderr, but quiet success reduces log noise—easy to spot issues.
- **Exit status as a contract.** Using `(( failed_count == 0 ))` at the end makes the script composable in larger automation workflows.
- **`--porcelain` for parsing.** `git status --porcelain` is designed for scripting and gives precise output format; `--quiet` just suppresses output.
- **The `find` syntax for `.git`.** Using `\( -type d -o -type f \) -prune -print0` correctly handles both submodule `.git` files and regular `.git` directories without duplicates.
